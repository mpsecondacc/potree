  Detailed Analysis: Root Causes of UI Issues Despite Material Isolation

  The material isolation test passes 4/4 because it only tests individual material properties,
  but there are 3 critical architectural layers where sharing still occurs, causing the UI
  problems you're experiencing.

  🔍 Issue #1: Attribute Range Slider "NaN to NaN" Problem

  Root Cause: viewer.js:1685-1686 in the update() method (called every frame):

  material.classification = this.classifications;  // SHARED REFERENCE!
  material.recomputeClassification();

  The Problem Chain:
  1. Shared Geometry: All viewers share the same pcoGeometry from SharedResourceManager
  2. Frame-Level Override: Every frame, viewer.update() forcibly assigns this.classifications
  to material.classification (line 1685)
  3. getAttribute() Data Corruption: When viewer 1 switches attributes, it modifies shared
  geometry buffers
  4. Range Calculation Failure: Viewers 2+ calculate ranges from corrupted attribute data,
  resulting in NaN

  Why Material Test Passes: The test only checks if materials are separate instances, not if
  their properties get overridden every frame.

  🔍 Issue #2: Classification Sharing Between Viewers

  Root Cause: Same viewer.js:1685 line - frame-level forced synchronization:

  The Problem Chain:
  1. Viewer 1 Changes Classification: Calls setClassificationVisibility(code, false)
  2. Event Propagation: Triggers classification_visibility_changed event
  3. Frame Update Override: Next frame, ALL viewers execute material.classification = 
  this.classifications
  4. Global State Pollution: Since this.classifications is modified, it affects all viewers'
  materials

  Why This Happens Despite Cloned Materials:
  - Material instances ARE separate (test confirms this)
  - BUT every frame, the update() method overwrites material.classification with
  viewer-specific this.classifications
  - Since the SharedResourceManager creates viewer instances that may share some references,
  classification changes propagate

  🔍 Issue #3: Why Material Isolation Test Passes But Real UI Fails

  The Disconnect:
  - Test Scope: Only validates that material1 !== material2 and basic property isolation
  - Real Runtime: Materials get continuously overwritten by the frame update loop
  - Missing Test Coverage: The test doesn't simulate the viewer.update() method that runs every
   frame

  🔧 Solution Architecture

  The solution requires 3-layer fixes:

  Layer 1: Stop Frame-Level Material Overrides

  Modify viewer.js:1685-1686 to only set classification if it hasn't been set or if explicitly
  requested:

  // BEFORE (current - causes sharing):
  material.classification = this.classifications;
  material.recomputeClassification();

  // AFTER (proposed - preserves isolation):
  if (!material._classificationInitialized || material._viewerId !== this.viewerId) {
      material.classification = this.classifications;
      material._classificationInitialized = true;
      material._viewerId = this.viewerId;
      material.recomputeClassification();
  }

  Layer 2: Fix Attribute Range Calculation

  Create viewer-specific attribute range calculation that doesn't depend on shared geometry
  buffers:

  // Calculate ranges from viewer-specific material state, not shared geometry
  const calculateViewerSpecificAttributeRange = (viewer, attributeName) => {
      // Use viewer-specific material uniforms instead of shared geometry

          return material.uniforms[`${attributeName}Range`].value;
      }

  }
