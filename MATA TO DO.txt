MATA TO DO - Point Cloud Material Sharing Between Viewports

## CRITICAL ISSUE: Material Instance Sharing
**Problem**: All viewers share the SAME material instance. Changes to material properties in one viewer immediately affect all other viewers because they reference the identical JavaScript object.

### Evidence from SharedResourceManager-NEW.js:
- Line 156: `viewerPointCloud.material = this.createViewerMaterial(sharedPC, viewerId);`
- Line 227: `const viewerMaterial = originalMaterial;` (direct reference, not clone)
- Lines 224-226: Comment explicitly states "Point cloud materials are typically shared and shouldn't need individual instances"

### Root Cause:
```javascript
createViewerMaterial(sharedPC, viewerId) {
    const originalMaterial = sharedPC.originalMaterial;
    
    // Point cloud materials are typically shared and shouldn't need individual instances
    // unless we need per-viewer customization
    const viewerMaterial = originalMaterial;  // <-- DIRECT REFERENCE, NOT CLONE
    
    // This creates a wrapper but still references the same underlying material object
    const materialWrapper = {
        ...originalMaterial,  // <-- STILL SHARES THE SAME OBJECT
        _viewerId: viewerId,
        _sharedResourceId: sharedPC.id,
        _isSharedResource: true,
        _originalMaterial: originalMaterial
    };
}
```

## REQUIRED ARCHITECTURAL CHANGES:

### 1. Material Instance Isolation
**Current**: All viewers share same material object
**Required**: Each viewer needs its own material instance
**Solution**: Modify `SharedResourceManager.createViewerMaterial()` to clone materials instead of sharing references

### 2. Deep Material Cloning
**Challenge**: Three.js PointCloudMaterial contains complex properties (textures, uniforms, shaders)
**Required**: Proper material cloning that preserves all properties but creates separate instances
**Solution**: Implement deep cloning for PointCloudMaterial with texture sharing but property isolation

### 3. Property Synchronization Strategy
**Options**: 
A) Complete isolation (each viewer has independent material settings)
B) Selective sharing (share textures/shaders, isolate visual properties like size, opacity, etc.)
C) Synchronized defaults with override capability

### 4. Performance Considerations
**Original Design**: Shared materials for memory efficiency
**New Requirement**: Individual materials for per-viewer customization
**Balance**: Share heavy resources (textures, geometry) but isolate property objects
