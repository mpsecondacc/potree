  DETAILED EXECUTION PLAN

  Root Cause Analysis

  1st Issue - Point Size Changes from 0.2 to n (Even with Single Viewer):
  - Location: profile.js:915 - target.size = 2;
  - Cause: The copyMaterial() function in ProfileWindow.render() copies all material
  properties from source to target, then HARD-CODES target.size = 2 for profile rendering
  - Effect: This overwrites the original material's size property, and since materials are
  shared references in multi-viewer, it affects all viewers

  2nd Issue - Multi-Viewer Profile Rendering Bugs:
  - Location: Multiple files - material sharing and ProfileFakeOctree instances
  - Cause:
    a. Shared Material References: SharedResourceManager-NEW.js creates material proxies
  that share underlying data
    b. Global ProfileWindow: Single #profile_window DOM element shared between all viewers
    c. ProfileFakeOctree Material Conflicts: Each viewer creates its own ProfileFakeOctree
  but they interfere with each other's rendering
    d. Rendering Context Conflicts: Multiple viewers trying to render to the same profile
  canvas

  Solution Strategy

  PHASE 1: Fix Material Isolation Issues
  1. Create ProfileMaterial-NEW.js - Dedicated material management for profiles
  2. Modify profile.js copyMaterial function - Deep clone materials instead of reference
  sharing
  3. Add viewer-specific material tracking - Prevent cross-contamination

  PHASE 2: Fix Profile Window Multi-Viewer Support
  1. Create ProfileWindowManager-NEW.js - Manage multiple profile windows per viewer
  2. Modify ProfileWindow constructor - Support viewer-specific DOM elements
  3. Update ProfileWindowController - Handle viewer-specific profiles

  PHASE 3: Fix ProfileFakeOctree Conflicts
  1. Create ViewerSpecificProfileRenderer-NEW.js - Isolated rendering contexts
  2. Modify ProfileFakeOctree material creation - Ensure complete isolation
  3. Add profile rendering state management - Prevent interference

  PHASE 4: Integration and Testing
  1. Update ViewerManager-NEW.js - Use new profile system
  2. Modify MultiViewerSidebar-NEW.js - Connect to new managers
  3. Create ProfileSystemRegistry-NEW.js - Central coordination

  Implementation Plan

  File Creation Priority:
  1. ProfileMaterial-NEW.js (Core material isolation)
  2. ViewerSpecificProfileRenderer-NEW.js (Rendering isolation)
  3. ProfileWindowManager-NEW.js (UI management)
  4. ProfileSystemRegistry-NEW.js (Central coordination)

  File Modification Priority:
  1. profile.js - Fix copyMaterial function and material sharing
  2. ViewerManager-NEW.js - Integrate new profile system
  3. MultiViewerSidebar-NEW.js - Update profile window calls
  4. SharedResourceManager-NEW.js - Add profile material isolation

  Key Technical Solutions:
  - Deep Material Cloning: Replace reference sharing with deep copies
  - Viewer-Specific Profile Windows: Each viewer gets its own profile DOM elements
  - Isolated Rendering Contexts: Separate THREE.js scenes and renderers per viewer
  - Material State Preservation: Store original material properties and restore after
  profile rendering
  - Profile Registry System: Central tracking of active profiles per viewer
