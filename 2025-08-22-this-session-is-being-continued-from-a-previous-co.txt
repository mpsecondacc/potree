  Current Implementation Issue: Missing i18n text resolution and missing Min Point Size slider entirely.

  2. Missing Point Sizing Selector

  Root Cause: The Point Sizing selector (optPointSizing) was completely omitted from the current implementation.

  From PropertiesPanel.js (lines 95-102):
  <label for="optPointSizing" class="pv-select-label" data-i18n="appearance.point_size_type">Point Sizing </label>
  <select id="optPointSizing" name="optPointSizing">
      <option>FIXED</option>

      <option>ADAPTIVE</option>
  </select>

  Current Implementation: Missing entirely from createPointCloudProperties().

  3. Shape Selector and Attribute Selector Hold-Click Behavior

  Root Cause: Missing jQuery UI selectmenu() widget implementation. The original uses selectmenu(), not standard HTML <select>.

  From PropertiesPanel.js (lines 312-320):
  let opt = panel.find(`#optShape`);
  opt.selectmenu({
      change: (event, ui) => {
          let value = ui.item.value;
          material.shape = PointShape[value];
      }
  });

  Current Implementation Issue: Uses standard <select> with change() events instead of jQuery UI selectmenu() widget.

  4. RGB Slider Behavior After Attribute Changes

  Root Cause: Complex material visibility system with conditional container hiding/showing.

  From PropertiesPanel.js (lines 541-545):
  let update = () => {
      attributeSelection.val(material.activeAttributeName).selectmenu('refresh');
  };
  this.addVolatileListener(material, "point_color_type_changed", update);
  this.addVolatileListener(material, "active_attribute_changed", update);

  The original implementation has:
  - Conditional container visibility: #materials.rgb_container, #materials.elevation_container, etc.
  - Material event listeners: point_color_type_changed, active_attribute_changed
  - Dynamic UI updates: Based on selected attribute type

  5. CRITICAL: Point Cloud Material Sharing Between Viewports

  Root Cause: SharedResourceManager-NEW.js deliberately shares materials between viewers.

  From SharedResourceManager-NEW.js (lines 221-227):
  createViewerMaterial(sharedPC, viewerId) {
      const originalMaterial = sharedPC.originalMaterial;

      // Point cloud materials are typically shared and shouldn't need individual instances
      // unless we need per-viewer customization
      const viewerMaterial = originalMaterial;

  Critical Issue: All viewers share the SAME material instance. Changes to material properties in one viewer immediately affect all other viewers because they reference the identical JavaScript
  object.

  Evidence from code:
  - Line 156: viewerPointCloud.material = this.createViewerMaterial(sharedPC, viewerId);
  - Line 227: const viewerMaterial = originalMaterial; (direct reference, not clone)
  - Lines 224-226: Comment explicitly states materials are shared

  Required Architectural Changes

  1. Material Instance Isolation

  Current: All viewers share same material object
  Required: Each viewer needs its own material instance
  Solution: Modify SharedResourceManager.createViewerMaterial() to clone materials instead of sharing references

  2. Selector Widget Implementation

  Current: Standard HTML <select> elements
  Required: jQuery UI selectmenu() widgets
  Solution: Replace all selector implementations with opt.selectmenu({change: callback})

  3. Missing UI Components

  Current: Incomplete properties panel
  Required: Full PropertiesPanel equivalent
  Solution: Add Point Sizing selector, Min Point Size slider, i18n text resolution

  4. Material Event System

  Current: Direct property assignment
  Required: Material event listeners and conditional UI updates
  Solution: Implement material event listeners (point_color_type_changed, active_attribute_changed) and conditional container visibility

  5. Core Dependencies

  Current: Simplified implementation
  Required: Full dependency chain
  Solution: Import PointSizeType, PointShape from defines.js, implement proper material event dispatching

  Complexity Assessment

  This requires core architecture changes to the SharedResourceManager and material management system. The material sharing issue alone requires fundamental rewrites to the resource management layer,
   as it was designed for performance optimization but breaks per-viewer customization.

  The fixes involve:
  1. Low-level material cloning (complex due to Three.js material internals)
  2. jQuery UI widget integration (moderate complexity)
  3. Event system implementation (moderate complexity)
  4. UI synchronization logic (high complexity due to conditional visibility)

  Estimated effort: Major refactoring affecting core systems.
