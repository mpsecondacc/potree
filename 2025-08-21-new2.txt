  Summary of Changes

  I've successfully rewritten the standard single-viewer Potree architecture to support our multi-viewer system, specifically resolving the EDL checkbox issue and other sidebar control problems.

  Key Architectural Changes

  1. New Multi-Viewer Sidebar Architecture

  Created: MultiViewerSidebar-NEW.js - Complete rewrite of original sidebar.js

  Core Differences:
  - Element ID Scoping: #chkEDLEnabled → #chkEDLEnabled_${viewerId}
  - Event Isolation: Uses event.stopPropagation() to prevent ViewerManager interference
  - Async initialization: Promise-based template loading and setup
  - Scoped DOM references: Each sidebar has isolated DOM context
  - ViewerManager compatibility: Designed to work with capture-phase event handling

  2. Event Handling Resolution

  Problem Solved: ViewerManager's capture-phase event listeners were intercepting sidebar control events

  Solution:
  - Added data-viewer-sidebar="true" attributes for proper event recognition
  - Used event.stopPropagation() in all control event handlers
  - Maintained natural browser checkbox behavior while preventing viewer interference

  3. Element Management System

  Original Approach:
  // Global element access (single viewer)
  $('#chkEDLEnabled').click(() => {
      this.viewer.setEDLEnabled($('#chkEDLEnabled').prop("checked"));
  });

  New Multi-Viewer Approach:
  // Scoped element access (multi-viewer)
  const chkEDLEnabled = this.dom.find(`#chkEDLEnabled_${this.viewerId}`);
  chkEDLEnabled.on('click', (event) => {
      event.stopPropagation(); // Critical for multi-viewer
      this.viewer.setEDLEnabled(event.target.checked);
  });

  4. Template Loading System

  Replicates original viewer.loadGUI() flow:
  1. Load sidebar.html template
  2. Update all element IDs with viewer suffixes
  3. Initialize internationalization (i18next)
  4. Set up accordion functionality
  5. Initialize appearance section with working controls
  6. Create hamburger button for UI access

  5. DOM Structure Changes

  Original: Single #potree_sidebar_container with global element IDs

  New: Per-viewer containers with scoped IDs:
  - Container: data-viewer-sidebar="true" + data-viewer-id="${viewerId}"
  - Elements: All IDs suffixed with _${viewerId}
  - Names: Form elements scoped to prevent conflicts
  - Labels: Updated for attributes to match new IDs

  6. Integration with ViewerManager

  Updated ViewerManager-NEW.js:
  - Import: MultiViewerSidebar-NEW.js instead of ViewerSidebar-NEW.js
  - Async initialization: await sidebar.init() instead of synchronous creation
  - Event handling: Sidebar controls properly recognized by isSidebarControlEvent()
